# External-style technical security review — 2 September 2026

## Assessor and assurance level

This review was performed by OpenAI Codex at the owner's request from the
perspective of a third-party security assessor. Codex is an AI technical
assessor, not an accredited penetration-testing laboratory. It also implemented
the remediations described below, so this report must not be represented as an
organizationally independent certification, CREST report, SOC report, or legal
attestation.

The owner authorized review of the Lekha Captions source and safe,
non-destructive probes of the public application and API. Denial of service,
social engineering, destructive payment activity, credential theft, real-user
account takeover, and persistence were excluded.

## Result

**Technical result: PASS WITH DEPLOYMENT CONDITIONS**

No Critical or High severity vulnerability was identified in the tested scope.
One Bandit Medium report was reviewed and suppressed with a narrow justification:
the private Railway worker readiness listener binds to all container interfaces
because the platform health proxy must reach it; the worker has no public domain
and exposes only readiness state.

Mass-launch security sign-off is conditional on deploying the reviewed commit,
verifying its immutable release marker, and completing authenticated staging
capacity and customer-journey tests. Production still reports an older backend
commit and the live frontend has no release marker.

## Findings and remediation

### SEC-2026-01 — Over-broad frontend connection policy

- Severity: Low, defense in depth
- Status: Remediated in the reviewed working tree; deployment pending
- Observation: the frontend CSP permitted `connect-src https:`, allowing a
  future injection weakness to send browser requests to any HTTPS origin.
- Fix: replace the scheme wildcard with explicit Lekha API, Firebase/Google,
  Razorpay, Sentry, and reCAPTCHA origins in Vite, Netlify, static-header, and
  Vercel configurations. A release contract now rejects the broad directive.

GitHub-hosted Chromium checks use `--no-sandbox` only when GitHub's `CI=true`
signal and the workflow's explicit `PUPPETEER_CI_NO_SANDBOX=1` are both present.
The production renderer continues to reject the general sandbox-disable switch;
the Railway-only container exception remains separately scoped to the hardened
container image.

### SEC-2026-02 — Static preview nonce

- Severity: Low, defense in depth
- Status: Risk accepted for the current static-hosting architecture
- Observation: generated template-preview `srcdoc` frames require a known nonce
  for their generated animation scripts. The preview markup is sanitized, the
  iframe content is generated by application code, template XSS tests pass, and
  the export renderer separately allows only known tags while blocking arbitrary
  network requests.
- Follow-up: move the generated preview sequencer to a fixed same-origin runtime
  or isolated preview origin when the template system is next redesigned.

### SEC-2026-03 — Historical personal identifier

- Severity: Low privacy/operational exposure
- Status: Removed from the current tree; Git-history remediation pending owner
  coordination
- Observation: four historical commits contain a former personal operator
  identifier in three documentation/patch files. No private-key marker was found.
- Follow-up: keep the repository private or coordinate a history rewrite and
  credential/contact review. Do not force-push rewritten history without
  coordinating every clone, deployment integration, and collaborator.

### SEC-2026-04 — Reviewed code is not the production release

- Severity: Medium release assurance
- Status: Open
- Observation: the live backend reports
  `419c3f1695efd925610a00cc8151ed0da9d1a8b1`; the reviewed local source began at
  `2a1f35306a581ef7d88e81c649efa33110cd9f41`, and the live frontend exposes no
  immutable release marker.
- Required closure: commit the reviewed changes, obtain green hosted CI, deploy
  frontend/API/worker from the same full Git SHA, and run
  `npm run launch:verify-deployed` with a saved release record.
